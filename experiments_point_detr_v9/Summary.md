### **Experiment Report: Unsupervised Physics-Based Stippling**

**Objective:**
To train a neural network to generate engineering-grade stippling (Blue Noise distribution) with precise coordinates, satisfying strict capacity and spacing constraints, without using a slow solver at inference time.

**Methodology:**

* **Architecture:** `StippleRefiner` (ResNet Backbone + Custom Transformer Block + Iterative Coordinate Updates).
* **Paradigm:** Unsupervised "Physics" Optimization. The model minimizes an objective function defining desired properties (Capacity + Spacing + Appearance).
* **Losses:**
* **Sinkhorn (Optimal Transport):** Enforces Capacity (Equal mass per point).
* **Repulsion:** Enforces Spacing (Blue Noise).
* **Render:** Enforces Visual Fidelity (Tone matching).



---

### **Key Findings & Failures**

#### **1. The "Blind Model" Failure (Spatial Agnosia)**

* **Observation:** The model reduced the Sinkhorn loss significantly but produced uniform noise that completely ignored the image content (rings).
* **Root Cause:** The Transformer received flattened image features without **Positional Encodings**. It knew "features exist" but not *where* they were.
* **Fix:** Added 2D Sine/Cosine Positional Encodings to the image features.

#### **2. The "Ghost Target" Failure (Coordinate Mismatch)**

* **Observation:** Sinkhorn loss dropped to near-zero (`0.001`), yet the output was still uniform noise.
* **Root Cause:** The training loop generated the "Target" point set using a mismatched coordinate system (`[-1, 1]` vs `[0, 1]`) or invalid image normalization. The model was successfully optimizing to match a target that was *itself* noise.
* **Fix:** Forced all coordinate systems (Model Init, Output, Target Generation, Loss Grids) to strictly `[0, 1]`.

#### **3. The "Clumping" Failure (Force Imbalance)**

* **Observation:** The model successfully formed rings (solved the "Blindness"), but points clumped together in lines or clusters rather than spreading out.
* **Root Cause:** The **Render Loss** (weight `10.0`) dominated the **Repulsion Loss** (weight `0.00002`). The model found it "cheaper" to stack points on dark pixels than to respect spacing.
* **Attempted Fix:** Drastically increased Repulsion weight (`5000.0`).

#### **4. The "Exploding Gradient" Failure (NaNs)**

* **Observation:** Increasing the repulsion weight caused the loss to explode to `NaN` instantly.
* **Root Cause:** The **Soft Repulsion** formula () creates infinite gradients when points overlap (dividing by zero).
* **Attempted Fix:** Switched to **Gaussian Repulsion** (bounded between 0 and 1) and added Gradient Clipping.

#### **5. Final Status: "Stuck in the Middle"**

* **Result:** Even with stable Gaussian repulsion, the model struggles to converge to a clean Blue Noise distribution. It oscillates between "grainy/clumped" (Render dominance) and "uniform/blurred" (Repulsion dominance).
* **Conclusion:** The Unsupervised Optimization landscape for this specific architecture is **ill-posed** and incredibly difficult to tune. The gradients from the conflicting losses (Pull to Dark vs. Push Away) are fighting each other rather than cooperating.

---

### **Decision: The Strategic Pivot**

Since you already possess a **Ground Truth (GT)** dataset (40,000 samples of perfect Blue Noise stippling generated by a solver), the unsupervised approach is unnecessary "hard mode."

**Next Step:** Refactor the project to **Supervised Learning**.

* **New Objective:** Train the model to move random points to match the *known perfect positions* from the dataset.
* **Primary Loss:** **Chamfer Distance** (Set-to-Set regression).
* **Benefit:** Numerical stability, faster convergence, and guaranteed "Engineering Grade" results because the model learns to mimic the exact solver logic you need .
